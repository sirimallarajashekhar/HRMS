## 2026-11-25 – P0.1 Solution skeleton
**Built:** Hrms.sln (.NET 10, central package management, warnings as errors); hosts Hrms.Api (Serilog JSON, OpenTelemetry, /health/live + /health/ready, built-in OpenAPI per API version via Asp.Versioning.OpenApi, Scalar in Development, problem details with stable `code` + `traceId`, correlation id, /api/v1 versioning, sample `GET /api/v1/ping`) and Hrms.Worker (Serilog, OpenTelemetry, heartbeat placeholder); SharedKernel (`Result`/`Error`); Contracts; empty Platform projects (Workflow, Policy, Notifications); Core module template (Domain/Application/Infrastructure/Api). 31 tests: unit, integration (WebApplicationFactory), architecture (modules discovered by naming convention; boundary rule proven by a failing fixture).
**Decisions:** built-in OpenAPI (not Swashbuckle); FluentAssertions pinned to 7.2.2 (v8 needs a commercial license); Microsoft.* packages pinned to 10.0.x (NuGet "latest" is 11.0 and does not run on net10.0); OpenAPI/Scalar not served in Production until P0.4; `InvariantGlobalization` deliberately NOT set (multi-country formatting); no FSD existed, built from the playbook prompt.
**Convention learned:** NetArchTest matches namespaces by prefix, so layer sub-namespaces must be nested (`Hrms.X.Domain.Events`), never siblings like `Hrms.X.DomainEvents`.

## 2026-11-25 – P0.2 Local infra and CI
**Built:** `docker-compose.yml` (MySQL 8.4 utf8mb4/UTC, Redis 7.4, RabbitMQ 4 + management UI, RustFS S3-compatible object store, Seq; all host ports env-configurable and bound to 127.0.0.1; `--profile app` also runs API + worker); `.env.example`; multi-stage non-root Dockerfiles for Hrms.Api and Hrms.Worker; GitHub Actions CI (build with warnings as errors + NuGet audit, unit/architecture/integration tests with Testcontainers MySQL, vulnerability scan, gitleaks, docker image builds, compose validation, job timeouts, actions pinned to SHAs); CD skeleton (GHCR publish restricted to main/`v*` tags with CI-green and version allow-list checks; dev -> staging -> prod with environment gates, placeholder deploy steps); Dependabot (nuget, docker, docker-compose, github-actions); real `/health/ready` checks for MySQL, Redis and RabbitMQ (TCP) that fail closed outside Development; Seq sink when `Seq:ServerUrl` is set; `launchSettings.json`; README "Run locally in 5 minutes", one-time GitHub setup and deploy notes. 40 tests (5 unit, 9 architecture, 26 integration incl. a real MySQL 8.4 container).
**Verified for real:** compose stack healthy; API container runs as uid 1654; `/health/ready` 200 -> 503 when Redis stopped while `/health/live` stays 200; logs arrive in Seq; both workflow files pass actionlint. **Not yet run:** the CI and CD workflows themselves (nothing pushed to GitHub Actions yet); the CD "CI is green" check via the checks API is unproven until the first run.
**Decisions:** Seq over Grafana/Loki (lighter); gitleaks (free for personal repos; needs `GITLEAKS_LICENSE` if the repo moves to an organisation); GHCR with placeholder deploys; RustFS 1.0.6 instead of MinIO (MinIO no longer publishes pullable images; production uses real S3 behind `IFileStorage`); custom health checks instead of AspNetCore.HealthChecks.* packages (fewer transitive version risks); Dockerfiles restore+publish in one step with a BuildKit NuGet cache mount (robust to new projects, no hand-kept csproj list).
**Learned:** Dockerfiles must COPY `.editorconfig` or analyzer settings differ in the image; host ports clash with other local projects, hence env-configurable ports; `dotnet build`/`test` must not run concurrently on the same tree.
